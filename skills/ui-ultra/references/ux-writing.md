# 界面文案 UX Writing（中文为主）

文案是界面的一部分。同样的布局，"提交成功！🎉" 和 "已保存 · 3 秒前" 传递的是完全不同的质感。

---

## 1. 语气

- **清楚 > 简洁 > 有个性**。先让人看懂，再让人觉得舒服，最后才是好玩。
- 像一个靠谱的同事说话：直接、具体、不卑不亢。不要客服腔（"亲～"）、不要公文腔（"系统检测到您的操作存在异常"）、不要营销腔（"开启全新智能体验"）。
- **称呼**：同一产品统一用"你"或"您"。工具/开发者/年轻用户用"你"；政务/金融/医疗/面向年长用户用"您"。
- 产品自称：尽量省略主语（"已保存"而不是"系统已为您保存"）；必须时用产品名，不用"小 X"之类的拟人昵称（除非是品牌定位）。
- 少用感叹号，一屏最多一个；不用 emoji 表达状态（✅❌ 交给图标）。

---

## 2. 标点与格式

- 中文语境用**全角标点**：，。、；：？！「」（）——……；数字、英文、代码内部用半角。
- 中英文、中文与数字之间加空格："使用 GitHub 登录"、"共 12 个文件"；数字与单位之间：`12 GB`、`3 天`；百分号、度数不加空格：`45%`、`30°`。
- 按钮、标签、菜单项、标题**不加句号**；完整句子的说明文字加句号。
- 引号：简体中文用 “ ” 或「」，全站统一一种。
- 省略号用 `…`（单字符），表示"还需进一步操作"的菜单项结尾加 `…`（"另存为…"）。
- 时间格式全站统一：`2026年11月5日 14:32`；同一年内可省略年份；跨时区时注明。
- 不要全角数字和全角英文字母（`１２３`、`ＡＢＣ`）。

---

## 3. 按钮与操作

| 场景 | ❌ | ✅ |
|---|---|---|
| 保存表单 | 提交 / 确定 | 保存更改 |
| 创建 | 新增 / 添加一个 | 新建项目 |
| 删除确认 | 确定 / 是 | 删除 3 个文件 |
| 取消 | 否 / 返回 | 取消（或"继续编辑"） |
| 付款 | 立即提交 | 支付 ¥299 |
| 引导链接 | 点击这里 / 了解更多 | 查看定价方案 |

- **动词 + 宾语**，2–6 个字；按钮文字要能回答"点了会发生什么"。
- 确认弹窗的按钮复述动作（"删除"/"取消"），不要"确定"/"取消"——用户不读正文也不会点错。
- 同一个动作全站同一个词：不要这里"删除"、那里"移除"、另一处"清除"（除非语义确实不同：移除 = 从列表拿掉，删除 = 永久消失）。

## 4. 错误信息

**公式：发生了什么 + 为什么（可选）+ 怎么办**

| ❌ | ✅ |
|---|---|
| 操作失败 | 保存失败：网络连接中断。已保留你的修改，恢复网络后点击重试。 |
| 输入格式错误 | 手机号应为 11 位数字 |
| Error 500 | 服务暂时不可用，我们正在处理。请稍后再试，或查看服务状态。 |
| 权限不足 | 你没有编辑此文档的权限。向所有者 张三 申请编辑权限 |
| 文件过大 | 文件超过 20 MB 上限。可以压缩后再上传，或升级到专业版（上限 2 GB）。 |

- 不责备用户（"你输入了错误的…"→"…应为…"）。
- 不暴露技术细节（堆栈、SQL、错误码可折叠在"详细信息"里供反馈用）。
- 告诉用户数据是否安全："已保留你的修改"能极大降低焦虑。

---

## 5. 空状态、加载与成功

- **空状态**：说明这里会有什么 + 如何开始。"还没有项目。创建第一个项目，开始组织你的工作。"
- **搜索无结果**："没有找到"会议纪要"相关的文档。试试更短的关键词，或 清除筛选。"
- **加载**：超过 3 秒要说明在做什么："正在生成报告（约 30 秒）…"；不要"加载中，请稍候…"一挂到底。
- **成功**：轻量、就地、可撤销。"已归档 · 撤销"；不要"恭喜您，操作成功！"。
- **破坏性操作**说清后果："删除后，项目中的 12 个文件和所有评论将无法恢复。"

---

## 6. 表单文案

- 标签用名词短语，不加冒号："邮箱地址"而不是"请输入您的邮箱地址："。
- placeholder 只放示例："name@company.com"；不放说明（放到标签下方的 hint）。
- hint 在填写前提示规则："至少 8 位，包含数字和字母"，而不是等报错才告诉。
- 选填项标"（选填）"，不要用红色星号标一屏必填项。

---

## 7. 数字、占位与真实感

- 示例数据要**像真的**：真实感的人名（张晓雨、Lin Wei）、合理的数值（¥128.40，而不是 ¥100.00）、近期日期。
- 不要用 Lorem ipsum 或"这是一段描述文字"；中文产品更不要用英文占位文本。
- 不编造数据与背书："10,000+ 团队信赖""提升 10 倍效率"——没有真实数据就写 `[待补充：客户数]`，交付时提醒用户替换。
- 不要硬编码"刚刚""今天"等相对时间到静态稿里。

---

## 8. 国际化预留

- 文字不要写进图片；按钮、标签宽度给英文/德文留 30–50% 余量（中文最短，翻译后会变长）。
- 不拼接句子："共 " + n + " 个文件" 在其他语言里语序会错；用 ICU 消息格式，并处理单复数。
- 日期、数字、货币用 `Intl.*` 按 locale 格式化。
